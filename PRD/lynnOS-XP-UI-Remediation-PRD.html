lynnOS XP UI 一致性修复

1. 背景与目标

lynnOS 是一个模拟 Windows XP 桌面环境的个人博客（dreamcore 氛围层）。项目内建设计规范 skills/windows-xp-ui/SKILL.md（下称「规范」）对视觉语言、窗口系统、桌面环境、图标、控件与氛围均有明确要求。

2026-10-22 依据规范对全量源码的审查发现以下事实：

证据链（审查发现 → 受影响用户与时刻 → 产品决策）：
  • 开始菜单「注销」「关闭计算机」按钮无任何行为，且暗示浏览器可关机 —— 访客点击后无任何反馈，破坏系统模拟的可信度 → 规范 §5.3 / §13 明确禁止 → 移除或赋予诚实行为。
  • 桌面仅 4 个图标，博客核心应用（文章档案、照片记忆、音乐收藏、技术笔记、我的博客）无桌面入口；其中「我的博客」注册后在整个 UI 中没有任何入口 —— 访客无法从桌面发现博客内容 → 规范 §5.1 要求桌面承载相关应用 → 补齐桌面入口。
  • 项目已有完整 XP PNG 图标库（assets/icons/xp），但工具栏、关于我、照片、对话框等大量位置使用 emoji 替代系统图标 —— 视觉风格割裂 → 规范 §7 / §13 明确禁止 emoji 图标体系 → 统一替换为 XP 风格图像素材。
  • 留言板「提交」按钮无处理逻辑，留言不保存 —— 访客留言后内容丢失且无反馈 → 规范 §9 / §10 禁止假控件 → 实现真实的本地留言功能。
  • 窄屏（≤768px）下窗口固定 600–820px 宽、开始菜单固定 380px，均溢出视口不可用 → 规范 §11 → 补齐窄屏适配。

目标（可观察结果）：修复完成后，访客在桌面即可发现全部博客应用；界面上不存在无行为的假控件；系统图标风格统一为 XP 时代图像素材；留言可真实提交并在本人浏览器中保留；窄屏下全部窗口与菜单保持可用。

2. 范围

优先级内容对应需求
P0 规范判定的高优先级违规：假控件、emoji 图标体系、桌面入口缺失、留言板假提交、窄屏不可用 FR-01 ~ FR-05
P1 中优先级体验与规范对齐项：文章导航、工具栏语义、技术笔记数据、开始菜单项语义、设计 token 统一、复选框外观、xp-theme.css 精简 FR-06 ~ FR-10
不做 不重写窗口管理器、不更换框架与路由、不改变现有壁纸/音效/开机动画机制、不为照片与音乐补真实媒体资源（本期仍以占位视觉呈现，仅去除 emoji）

完成条件：规范「§12 视觉验证」12 项检查在当前实现下全部通过；本 PRD 的 P0 需求逐项可演示。

3. 产品模型

主要用户：博客访客（浏览者）。触发：打开网站、完成开机动画后进入桌面。完成条件：访客能从桌面或开始菜单打开任一博客应用，阅读内容，留言并得到反馈；在所有路径上不遇到无响应控件。共享对象：桌面图标、开始菜单项、应用窗口、留言条目 —— 其名称与状态在本文 §5 统一定义。

4. 功能性需求

需求 ID 稳定引用；优先级标注于标题后。通用约束统一收敛于 §5 共享规则，各需求内不重复。

FR-01 开始菜单底部操作区 P0

4.1.1 目的

消除「假装能关机」的控件，同时保留 XP 开始菜单的完整仪式感。

4.1.2 布局与内容

开始菜单底部操作区保留两个按钮，但语义修正为：

按钮图标新文案行为
左users-group.png返回欢迎页关闭全部已打开窗口，重新打开「Welcome」窗口，关闭开始菜单
右shutdown.png进入睡眠播放 XP 风格「关机」过场（见 4.1.4），关闭开始菜单

文案不得再出现「注销」「关闭计算机」字样。

4.1.3 触发

开始菜单处于打开状态时，访客点击底部对应按钮。

4.1.4 处理规则 —— 睡眠过场

点击「进入睡眠」 → 播放关闭音效（复用现有音效机制，遵循音效开关） → 全屏覆盖层淡入：XP 风格蓝黑渐变画面 + 居中文字「Somewhere.exe 正在进入睡眠…」 → 停留约 2.5 秒 → 覆盖层内出现「按任意键唤醒」提示 → 访客按任意键或点击 → 覆盖层淡出，回到桌面（桌面状态保持不变）
  • 过场期间覆盖层拦截全部指针事件；任务栏与窗口不销毁。
  • 「返回欢迎页」不得清空留言、设置等本地数据（见 SR-03）。

4.1.5 结果与状态变化

按钮行为可观察、文案诚实；开始菜单在任一操作后关闭。

4.1.6 例外

  • 音效关闭时过场静默播放。
  • 过场中再次点击「进入睡眠」不可达（覆盖层已拦截）。

FR-02 桌面图标与博客应用入口 P0

4.2.1 目的

让访客不开开始菜单也能发现博客全部核心应用；消灭「注册了但无入口」的死应用。

4.2.2 桌面图标集（最终态）

顺序图标标签打开应用

2notepad-file.png我的博客my-blog
3folder-documents.png文章档案article-archive
4folder-pictures.png照片记忆photo-memory
5folder-music.png音乐收藏music-collection

7document-edit.png留言板guestbook
8my-computer.png我的电脑my-computer

4.2.3 处理规则

  • 沿用现有交互：单击选中（高亮态）、双击打开、点击空白处取消选中。
  • 桌面图标区域宽度由当前 180px 扩展为可容纳两列网格，纵向按视口高度自动换列；窄屏规则见 FR-05。
  • 「显示桌面图标」设置项关闭时，以上全部图标隐藏（现有行为保留）。

4.2.4 结果与状态变化

桌面首屏可见全部 9 个入口；选中态与打开行为与现有实现一致。

4.2.5 例外

  • 视口高度不足一列放满时，允许横向扩展出第二列，不得出现图标遮挡任务栏。

FR-03 系统图标统一为 XP 图像素材 P0

4.3.1 目的

执行规范 §7：界面内任何承担「图标」角色的视觉元素一律使用 XP 风格图像素材，禁止以 emoji 或现代线性图标替代。文字修饰性符号（如提示框前的装饰字符）不在此限，但本迭代统一按下列映射清理。

4.3.2 替换映射表

位置现状替换为

4.3.3 处理规则

  • 所有图像图标使用 16/32/48px 三档原生尺寸渲染，禁止拉伸；image-rendering 不强制像素化（沿用现状）。
  • 文字字符「◀ ▶ ▲ ▼」属于几何符号而非 emoji，工具栏按钮可继续使用；若后续补充 XP 箭头素材再行替换。

4.3.4 结果与状态变化

全站界面不再出现任何 emoji 作为图标；图标风格在桌面、窗口、对话框、应用内保持一致。

FR-04 留言板：真实提交与本地保存 P0

4.4.1 目的

让访客留言真实生效并仅保存在访客本人浏览器中，与窗口内「保存在本地浏览器中」的既有文案一致。

4.4.2 布局

沿用现有布局：留言列表（可滚动）+ 底部输入区（昵称输入、留言输入、提交按钮）。

4.4.3 触发

访客在留言板窗口点击「提交」。

4.4.4 字段与校验

字段必填规则校验失败反馈
昵称是去除首尾空白后 1–20 字符XP 风格系统对话框（图标 error.png），文案指明缺失项；输入框保留已填内容
留言是去除首尾空白后 1–200 字符

4.4.5 处理规则

提交 → 校验（4.4.4）→ 失败：弹出错误对话框，不写入 → 成功：生成留言条目 {昵称, 留言, 提交日期(本地, YYYY-MM-DD)} → 追加到本人浏览器的留言存储，列表立即按「最新在前」重渲染 → 清空留言输入框，昵称保留 → 状态栏更新为「留言板 · N 条留言」
  • 首次打开时若本地无数据，展示现有 2 条演示留言作为初始内容，并保留底部「演示数据，保存在本地浏览器中」说明。
  • 留言内容按纯文本存储与渲染，访客输入的任何标记符号都原样显示为文字（防注入）。

4.4.6 结果与状态变化

新留言刷新页面后仍存在（同一浏览器）；「清除本地数据」设置项执行后留言恢复为演示初始状态（与现有清除语义一致）。

4.4.7 例外

  • 存储不可用（隐私模式等）：提交后弹出提示对话框说明无法保存，列表仅在当前会话内显示新留言。
  • 空列表（用户清除了全部数据且演示数据被禁用时——本期不开放删除单条留言，故不会出现空列表；若出现，显示「还没有留言」空态文案）。

FR-05 窄屏响应式适配 P0

4.5.1 目的

在 ≤768px 宽度设备上保持 XP 视觉身份，同时让窗口、开始菜单、任务栏全部可用。

4.5.2 处理规则

对象≤768px 时的行为
应用窗口打开时直接进入最大化态；最大/还原按钮与拖拽、缩放把手禁用；窗口内容保持可滚动
窗口默认尺寸所有默认宽度、最小宽度超过视口的值，按视口宽度钳制
开始菜单宽度 = min(380px, 100vw)；右列宽度按比例收缩，不出现横向溢出
任务栏开始按钮与系统托盘保留；任务按钮最小宽度收缩（120px → 72px），标题省略号截断
桌面图标单列排布、可纵向滚动区域不溢出任务栏；触控点击一次即选中，再点一次（≈双击）打开——沿用浏览器双击兼容，不单独实现手势
系统对话框最大宽度 = 100vw - 16px
  • 断点仅设 768px 一档；桌面宽屏行为完全不变。
  • 窄屏下从窗口化恢复为宽屏（旋转/拖大窗口）时，已最大化的窗口保持最大化，其余按原逻辑。

4.5.3 结果与状态变化

≤768px 视口下：所有应用可打开、可阅读、可关闭；无内容被任务栏遮挡；无横向滚动条。

FR-06 文章阅读器：上一篇 / 下一篇 P1

4.6.1 处理规则

  • 阅读器底部操作区新增两个按钮：「‹ 上一篇」「下一篇 ›」与既有「返回档案」并列。
  • 排序口径与文章档案列表一致（按日期倒序）；上一篇 = 列表中当前文章的前一条。
  • 已是首篇时「上一篇」禁用置灰；已是末篇时「下一篇」禁用置灰。
  • 点击后在同一窗口内切换文章：窗口标题、正文、分类、标签、字数统计同步更新。

4.6.2 例外

  • 仅 1 篇文章时两个导航按钮均禁用。

FR-07 工具栏与菜单栏语义治理 P1

4.7.1 处理规则

  • 所有应用共享的菜单栏（文件/编辑/查看/收藏/工具/帮助）保留为纯展示元素，但去除 hover 高亮（避免暗示可点击），样式改为静态文本。
  • 「所有程序」行：去除右侧箭头暗示，点击行为保留（打开「我的电脑」），文案改为「我的程序」。[Assumption, TBD：是否实现真正的级联程序菜单，待后续迭代评估]
  • 工具栏按钮统一遵循 SR-01：无行为的按钮一律带禁用态；「向上」在根层级时禁用。
  • 开始菜单左列第一项「电子邮件」更名为「关于我」（与实际打开的应用一致），图标保持 internet.png 或改为 user-key.png。

FR-08 技术笔记接入真实数据 P1

4.8.1 处理规则

  • 为 7 个分类各准备至少 1 篇真实笔记条目（标题 + 摘要 + 正文），数据结构复用文章档案的文章对象（标题/日期/分类/标签/正文）。
  • 分类侧栏点击切换列表；列表双击在文章阅读器中打开（与文章档案一致的阅读体验）。
  • 空分类显示「该分类暂无笔记」空态，不再显示示例代码占位。

FR-09 设计 token 与主题对齐 P1

4.9.1 处理规则

  • 正文主色 --text-primary 调整为近黑（#1a1a1a 至 #000000 区间取值）；窗口边框色统一为 #0054e3 单一来源（现状值保留，token 名归一为 --xp-window-border）。
  • 设置面板复选框替换为 XP 风格自定义勾选框（13px 见方、白底、灰边框、蓝色对勾），禁用浏览器默认 accent-color 方案。
  • xp-theme.css（第三方 XP.css 拷贝）中已被自定义窗口/任务栏样式完全覆盖的规则予以移除，消除「override 补丁层」；保留仍被引用的基础控件样式。[Assumption, TBD：精简范围以构建后视觉回归为准]

FR-10 开始菜单项完整性核对 P1

4.10.1 处理规则

  • 开始菜单左列补充「我的博客」入口（与 FR-02 桌面入口同源同图标）。
  • 开始菜单右列「我的文档/我的图片/我的音乐」与左列「文章档案/照片记忆/音乐收藏」指向同一应用——保留现状（XP 原逻辑即如此），但窗口地址栏文案统一为应用名。

5. 共享规则

SR-01 假控件禁令（全局）：任何可见控件必须具备可观察行为；无行为的控件必须删除或呈现禁用态。该规则优先级高于「还原 XP 外观」。

SR-02 图标使用规范（全局）：图标一律取自 assets/icons/xp/{16,32,48} 或后续补充的 XP 风格图像素材；禁止 emoji 作为图标；新增图标须先补素材再上线。

SR-03 本地数据语义（全局）：访客数据（留言、设置）仅保存在其本人浏览器；「清除本地数据」= 恢复初始演示状态；任何「重置/注销/返回欢迎页」类操作不得清除访客数据。

SR-04 对话框规范（全局）：系统对话框统一使用 XP 标题栏 + 图像图标（help.png 信息 / error.png 警告与错误）+ 居中按钮；禁止传入 emoji 图标。
